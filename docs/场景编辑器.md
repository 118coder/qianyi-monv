# 场景编辑器（图块搭建）

创作工坊的第六个模块，RPG Maker 式的图块绘图板：选图块 → 在画布上画 → 存成 JSON。

---

## 一、它和「关卡」页是什么关系

| | 关卡页 | 场景页 |
|---|---|---|
| 数据来源 | **程序生成**（BSP + A* 走廊） | **手工绘制**的图块 |
| 编辑对象 | 生成参数（层号 / 种子） | 每一格放哪个图块 |
| 用途 | 调游戏实际会跑的地牢 | 搭手工场景（房间原型、剧情场景、关卡草图） |

两者不冲突：地牢仍然是程序生成的，场景页负责"想自己摆的时候能摆"。

---

## 二、界面

```
┌────────────┬──────────────────────────────┬────────────┐
│ 图块集 ▾    │ 画笔 橡皮 填充 │ 适应窗口 撤销 重做 │ 场景名     │
│ 导入 刷新   ├──────────────────────────────┤ 宽 40 高 24│
│            │                              │            │
│ 图块调色板  │        画 布                  │ 图层列表    │
│ （16×12）   │  滚轮缩放 / 中键拖动 / 右键擦   │ ＋ 图层 删除│
│            │                              ├────────────┤
│ 笔刷：#37   │ 格 (12, 7) 图块 #37 层「地面」 │ 保存 载入   │
└────────────┴──────────────────────────────┴────────────┘
```

**三个区域的分工**：左边选笔刷、中间画、右边管场景结构与存档。工具条上的按钮是互斥的开关，
当前工具在状态栏会显示操作提示。

## 三、核心能力

### 3.1 图块集

- 自动扫描 `assets/tiles/*.png`，按当前场景的 `tile_size`（默认 32）切成网格；
- **「导入 PNG」** 打开文件对话框，选中后复制进 `assets/tiles/` 并立即生效；
- **不走 Godot 的导入系统**：用 `Image.load` 直接解码成 `ImageTexture`。
  这样外部图片放进来就能用，不需要等编辑器生成 `.import`、也不需要重启。

现有素材（512 宽的 RPG Maker 风格图块集）在 32px 网格下都是 16 列：

| 文件 | 尺寸 | 网格 |
|---|---|---|
| Dungeon_Cave_TileA2 | 512×384 | 16×12 |
| Dungeon_TileA4 | 512×480 | 16×15 |
| Overworld_TileA2 | 512×384 | 16×12 |
| TileA1 / TileA2 | 512×384 | 16×12 |

### 3.2 绘制

| 操作 | 效果 |
|---|---|
| 左键拖动 | 连续放置当前图块 |
| 右键拖动 | 擦除（置空） |
| **Alt + 左键** | 吸管：取当前格的图块作为笔刷 |
| 滚轮 | 以鼠标位置为锚点缩放（0.15× ~ 6×） |
| 中键拖动 | 平移视图 |
| 「填充整层」工具 | 点一下把整个图层铺满当前图块 |

### 3.3 图层

- 默认「地面」「装饰」两层，可增删；
- 每层独立的 `int` 数组，上层覆盖下层；
- 眼睛图标切换可见性（只影响显示，不改数据）；
- 绘制只作用于**当前选中层**。

### 3.4 撤销 / 重做

按「笔」为单位记快照（一次拖动 = 一步），最多 40 步。`Ctrl+Z` / `Ctrl+Shift+Z`。

### 3.5 画布性能

只画屏幕内的格子：按 `off / zoom` 反算可见行列范围。
40×24 的场景在任何缩放下最多画满一屏（约 1200 格 × 图层数），
200×150 的大图也一样。`_draw` 是事件驱动的，静止时不重绘。

## 四、数据结构

存到 `data/scenes/scene001.json`：

```json
{
  "version": 1,
  "name": "新场景",
  "tile_size": 32,
  "width": 40,
  "height": 24,
  "tileset": "res://assets/tiles/TileA2.png",
  "tileset_cols": 16,
  "tileset_rows": 12,
  "layers": [
    { "name": "地面", "visible": true, "data": [37, 37, -1, ...] },
    { "name": "装饰", "visible": true, "data": [-1, -1, 5, ...] }
  ]
}
```

`data` 是行优先的一维数组，长度 = `width × height`；`-1` 表示空。
图块序号 = `行 × tileset_cols + 列`。

**刻意做成最朴素的形式**：将来要在游戏里加载手搭场景，读这份 JSON 不需要任何转换层——
`idx` 直接反算出图块集里的 `region_rect` 就能画。

## 五、以后怎么让游戏读它

目前场景只存不改游戏。接进游戏最小的一步：

1. `ArpgWorld` 加一个 `load_tile_scene(path)`：按图层逐格画到 `_draw`；
2. 用 `TileMapLayer` 会更省，但现有渲染是自绘的，先对齐现有结构更稳；
3. 碰撞：`-1` 之外是否可走需要一个"可通行"标记，可以在图块集层面加一张 0/1 掩码图，
   或者按图层约定（地面层全可走、装饰层按图块序号查表）。

这一步没做，是因为它涉及"手搭场景和程序生成地牢如何共存"的产品决策
（是替换某一层？还是做成特殊房间？），需要先定玩法再动代码。

## 六、已知取舍

- **填充是"整层填充"而不是洪水填充**：地牢场景里整层填满更常用，洪水填充等有需要再加；
- **没有矩形选择/复制粘贴**：单块绘制 + 撤销已能覆盖当前需求；
- **不做自动图块（auto-tile）**：RPG Maker 的 A2 图块靠边缘自动拼，需要 47 张掩码图，
  现有素材是 A1/A2/A4 混排，先按普通图块处理；
- **场景尺寸改动会丢超出部分**：保留重叠区域，超出边界的内容直接丢弃（有撤销可回退）。
