# 创作工坊架构：EditorPlugin 扩展 + 独立创作工具

两个宿主，一份编辑内核。

---

## 一、为什么是两个而不是一个

「在 Godot 里也能编辑」和「完全不打开 Godot 也能编辑」是两种使用场景，不是重复建设：

| 场景 | 适合谁 | 优势 |
|---|---|---|
| **独立创作器**（`打开创作器.bat`） | 不想碰引擎、只想填内容和调数值的人 | 双击即开，界面完全可控，不受引擎版本影响 |
| **编辑器插件**（Godot 主屏页签） | 同时在写代码、要边改边看的人 | 和编辑器共享一套运行配置，试玩能用调试器与断点 |

如果只做一个，总有一类人被排除。所以做成两套**外壳**，共用同一份**内核**。

---

## 二、分层与职责

```
creator/
├── core/                    ← 共享内核（两套宿主都 import 这里）
│   ├── ui_kit.gd            控件工厂 + 主题 + 字段名中文化 + 动效工具
│   ├── data_store.gd        读写 / 原子写 / 备份 / 校验
│   ├── event_editor.gd      可视化事件编辑器（触发器 + 命令链 + 分支）
│   ├── dungeon_view.gd      地牢预览画布
│   └── workspace.gd         五个模块 + 保存 / 脏标记 / 状态广播  ← 唯一共用实体
├── creator.gd               ← 独立版外壳（120 行）
└── creator.tscn

addons/qy_creator/
├── plugin.cfg
├── plugin.gd                ← 编辑器扩展（注册主屏、精简页签、菜单）
└── main_screen.gd           ← 插件外壳（40 行）
```

**职责边界写成硬约束**：

| 层 | 负责 | 明确不做 |
|---|---|---|
| `core/*` | 编辑、校验、保存、预览、状态广播 | 不创建窗口、不决定试玩方式、不碰 `EditorInterface` |
| 独立外壳 | 窗口标题、起进程试玩、关闭 | 不实现任何编辑逻辑 |
| 插件外壳 | 注册主屏、隐藏页签、`play_main_scene()` | 同上 |

结果：两个宿主的胶水代码加起来约 160 行，编辑逻辑一份。

---

## 三、共享是怎么抽出来的

最初的版本把五个模块和窗口外壳全写在 `creator.gd` 里，导致插件要复用就只能复制一份。
这次拆成三层：

1. **`workspace.gd`** 承接全部编辑能力，自身是一个 `VBoxContainer`（工具条 + 左导航 + 内容区 + 状态条），
   只通过三个信号与外界交互：
   - `dirty_changed(is_dirty)` —— 宿主决定要不要在标题上加星号
   - `status_changed(msg, level)` —— 宿主决定要不要转发到编辑器状态栏
   - `playtest_requested()` —— 宿主自己实现「怎么试玩」
2. **独立版**连 `playtest_requested` → `OS.create_process()` 起新进程。
3. **插件版**连 `playtest_requested` → `EditorInterface.play_main_scene()`。

这就是全部差异。改一个字段的编辑逻辑，两边同时生效。

## 四、关键改动点

### 4.1 编辑器扩展的注册流程（只用官方扩展点）

```gdscript
func _has_main_screen() -> bool:      return true          # 编辑器自动加页签
func _make_visible(on: bool) -> void: _screen.visible = on  # 切页回调
func _get_plugin_name() -> String:    return "千亿魔女"      # 按钮文案
func _get_plugin_icon() -> Texture2D: return ...get_icon("Tools", "EditorIcons")
```

主屏容器挂在 `EditorInterface.get_editor_main_screen()` 下，生命周期交给编辑器；
`_exit_tree` 里 `queue_free()` 并移除菜单项，禁用插件即完全还原。**不改一行引擎代码。**

### 4.2 页签精简（让编辑器像专用工具）

隐藏 `3D` / `AssetLib`（中文环境是"资产库"/"资源商店"）：

- **按文案匹配而不是按下标**：按钮顺序随版本变化，下标不可靠；
- **等两帧再执行**：按钮行在布局完成且翻译写入之后才稳定，太早执行匹配不到 text；
- **只 `visible = false`，不删节点**：顶部「项目 → 工具」菜单里有「恢复编辑器默认页签」随时还原；
- 匹配不到就静默跳过，不报错。

### 4.3 视觉定调（工业实用）

一句话：**暖近黑 + 暖白 + 单一铜橙**，配合发丝线与等宽数字，做出一台仪表盘而不是一张落地页。

| 维度 | 决策 | 理由 |
|---|---|---|
| 底色 | `#0E0D0C` 暖黑，不用纯黑 | 纯黑压纯白是模板感最重的组合 |
| 文字 | `#F5F1EA` 暖白（对比约 15:1） | 长时间阅读不刺眼 |
| 强调 | `#E8873A` 铜橙，**只给保存按钮、当前选中、主操作** | 单屏一个强调色，不拿去装饰 |
| 分类 | 五个模块各一条 3px 色带（灰/铜/苔绿/紫/青） | 分类靠色带不靠正文，避免五颜六色 |
| 字体 | 中文微软雅黑；**所有数字/坐标/种子用 Consolas** | 等宽数字读数不跳宽，这是仪表感的主要来源 |
| 圆角 | 2~4px，配 1px 发丝线 | 不做大圆角卡片和投影 |
| 动效 | 切模块时内容错峰淡入，0.26s，最多 8 个元素 | 一次编排好的入场，胜过零散微交互；工作台频繁切换，动画必须短 |

**一个踩过的坑**：入场动画最初同时动 `position.y` 和 `opacity`，但内容都长在 `Container` 里，
Container 每帧会重写子节点 position，位移会被立刻打回原位。现在只动 `opacity`。

### 4.4 保存安全

`data_store.gd` 的三条硬规矩（这两个 JSON 就是游戏运行时读的文件，写坏等于游戏打不开）：

1. **原子写**：先写 `.tmp` 再 `rename` 覆盖，中途崩溃只留下 tmp，正式文件始终完整；
2. **写前备份**：`xxx.bak.0/.1/.2` 滚动保留 3 份；
3. **写前校验 + 写完回读**：结构不对直接拒绝，写出的 tmp 读不回来也放弃覆盖。

## 五、怎么用

**独立版**：双击根目录 `打开创作器.bat`。

**插件版**：打开 Godot 编辑器 → 顶部主屏按钮多出一个「千亿魔女」→ 点进去。
首次启用后在「项目 → 项目设置 → 插件」里可以看到 `千亿魔女 · 创作工坊`。
顶部菜单「项目 → 工具」下有「保存创作数据」和「恢复编辑器默认页签」。

## 六、验证方式

**静态（已做）**

- 全部脚本 `--check-only` 解析通过（`creator/core/*.gd`、`creator/creator.gd`、`addons/*/*.gd`）；
- 无残留旧路径引用（`ui_form.gd` / `data_io.gd` 已全部替换为 `core/ui_kit.gd` / `core/data_store.gd`）。

**实机（需要你做）**

| # | 验证点 | 期望 |
|---|---|---|
| 1 | 双击 `打开创作器.bat` | 窗口标题「千亿魔女 · 创作工坊」，左侧五个模块可切换，切换时内容淡入 |
| 2 | 改任意数值 → 保存 | 状态栏提示"已保存并备份"，`data/balance.json` 的 mtime 更新，目录出现 `.bak.0` |
| 3 | 游戏运行中改数值并保存 | 游戏内下一帧热重载套用，无需重启 |
| 4 | 事件页：新建事件 → 加对话 → 保存 | 重开创作器后事件还在；进游戏第 1 层触发对应对话 |
| 5 | 关卡页改层号/种子 | 预览立即重绘；把种子填进「数值 → 地牢种子」后游戏内布局一致 |
| 6 | 打开 Godot 编辑器 | 主屏多出「千亿魔女」页签；3D 与资产库页签消失 |
| 7 | 插件版点「试玩」 | 编辑器直接运行主场景（走编辑器运行配置） |
| 8 | 「项目 → 工具 → 恢复编辑器默认页签」 | 3D/资产库回来，创作页签不受影响 |
| 9 | 禁用 `qy_creator` 插件 | 页签消失、菜单项移除、编辑器恢复原状，无报错 |

**已知取舍**

- 编辑器里首次切到「千亿魔女」页时会生成一次地牢预览（约几十毫秒），可接受；
- 页签精简靠文案匹配，引擎改文案就失效——失效表现是「没隐藏」，不会报错，可用菜单恢复；
- 事件改动不会热重载到正在运行的局内（`map_events` 在开局时加载），需重开一局。
