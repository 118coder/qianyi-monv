# 编辑器可视化与中文化

本文说明「打开 Godot 编辑器为什么画面是空的、右边为什么一堆英文」，以及把这套工程改造成可视化工作台的做法与边界。

---

## 一、两个问题的根因

### 1.1 2D 视图空白

`arpg/main.tscn` 原本只有一个空的 `Node2D` 根节点：

```
[node name="ArpgMain" type="Node2D"]
script = ExtResource("1_arpg")
```

地牢、敌群、玩家、HUD 全部由 `main.gd` 的 `_ready()` 里用代码 `new` 出来。
而未标记 `@tool` 的脚本在编辑器里**根本不执行 `_ready()`**，所以：

- 场景树里只有一个孤零零的根节点；
- 2D 视口只有一个小小的节点图标；
- 检查器没有任何可调参数（因为 `main.gd` 里一个 `@export` 都没有）。

这不是 bug，是「纯代码驱动场景」的必然结果。但它让整个工程在编辑器里不可读、不可调。

### 1.2 检查器里的英文

Godot 编辑器的界面文本走 `TTR()`（tool 翻译域），官方 zh_CN 翻译覆盖了菜单、面板、按钮，
但**检查器的属性名与分组标题长期没有覆盖**——`Position` / `Rotation` / `Scale` / `Transform` /
`Visibility` / `Ordering` / `Texture` / `Material` 这些取的是属性名直译，翻不到就显示原文。

所以出现「界面中文 + 属性英文」的割裂。这跟项目代码无关，是引擎侧翻译缺口。

---

## 二、解决方案（四层）

| 层 | 文件 | 作用 |
|---|---|---|
| ① 预览层 | `arpg/editor_preview.gd` | 在编辑器里把地牢生成结果画进 2D 视口 |
| ② 配置层 | `arpg/main.gd` 的 `@export` 组 | 检查器第一屏变成中文参数，勾选即生效 |
| ③ 结构层 | `arpg/main.tscn` | 预置「世界 / 队伍 / 镜头 / 界面」四个容器，场景树可读 |
| ④ 中文化 | `addons/arpg_zh_editor/` | 注入 Translation，补全检查器属性名的中文 |

### 2.1 预览层

`@tool extends Node2D`，挂在 `main.tscn` 下。编辑器里执行：

1. 用 `ArpgDungeon.generate(floor, seed)` 生成一张图（固定种子 = 可复现）；
2. `_draw()` 画：深灰墙体打底、浅灰地板（逐行合并，1408 格压到几十条绘制指令）、
   房间按类型描边（绿=出发 / 黄=楼梯 / 橙=宝箱房 / 白=普通）并标序号、起点圆点、
   楼梯方框、宝箱菱形、顶部信息条（层号 / 尺寸 / 种子 / 房间数 / 可达率）。

运行时不参与任何逻辑：`_ready()` 里检测到非编辑器环境就 `queue_free()`，零开销。

可调参数（检查器里全中文）：

| 参数 | 默认 | 说明 |
|---|---|---|
| 地牢 → 层号 | 1 | 预览哪一层（越深越大：44×32 → 47×33） |
| 地牢 → 种子 | 20261103 | 同种子永远同一张图，便于复现与截图 |
| 地牢 → 换一张图 | 关 | 勾一下随机换种子（用布尔量当按钮） |
| 显示 → 墙体 | 开 | 关掉只看地板，画面更亮 |
| 显示 → 房间 | 开 | 房间边框与序号 |
| 显示 → 标记 | 开 | 起点 / 楼梯 / 宝箱房 |
| 显示 → 信息条 | 开 | 顶部统计 |
| 显示 → 不透明度 | 1.0 | 调到 0.3 可当底图叠用 |

**「预览和游戏不一致」的根因（第二版修正）**：第一版 `_rebuild()` 直接读
`ArpgBalance.MAX_FLOOR` 来决定层号上限，但编辑器里静态变量的初始化时序不稳，
它可能还是 0。而生成器内部的判据是：

```gdscript
boss_floor = floor >= ArpgBalance.MAX_FLOOR
```

`MAX_FLOOR` 一旦是 0，**任何层都会命中 Boss 层分支**——分支里只有一句
`_add_room(Rect2i(5, 4, 26, 18))` 然后 `return`，于是预览画出来就是
「一整块浅灰大房间 + 一个绿色起点圆点，没有走廊、没有楼梯」，跟游戏里的迷宫完全对不上。

现在三道保险一起上：

1. `_rebuild()` 里先 `Balance.reload_data()`，强制刷新静态表；
2. `if Balance.MAX_FLOOR < 2: Balance.MAX_FLOOR = 5` 直接修正静态值；
3. 生成后二次校验：`if dd.boss_floor and lv != max_floor` 说明判定仍然异常，按普通层重生成。

信息条会明确写出「普通层 / Boss 层 · 第 N 层 · 尺寸 · 种子 · … · 与游戏一致 / 示意」，
一眼就能看出画的是不是想要的那一层。

### 2.2 配置层

`main.gd` 顶部新增三组可视化旋钮，默认值与改动前行为完全一致（老存档、测试、命令行参数都不受影响）：

| 分组 | 参数 | 默认 | 作用 |
|---|---|---|---|
| 开局 | 起始层 | 1 | 调试时直接从第 N 层开始 |
| 开局 | 开局队友数 | -1 | -1 = 读 `balance.json`；0~8 = 强制 |
| 地牢 | 地牢种子 | 0 | 0 = 每层随机；固定值 = 布局可复现（叠加层号） |

优先级：命令行 `--friends=N` > 检查器配置 > `balance.json`。

### 2.3 结构层

`main.tscn` 预置四个空容器，`main.gd` 通过 `_slot("世界")` 之类的助手优先复用：

```
ArpgMain (Node2D) [main.gd]
├── 世界     (Node2D)      ← world 挂这里
├── 队伍     (Node2D)      ← z_index=5, y_sort_enabled，队友挂这里
├── 镜头     (Node2D)      ← CameraDirector 挂这里
├── 界面     (CanvasLayer) ← HUD 挂这里
└── 编辑器预览 (Node2D) [editor_preview.gd]
```

`_slot()` 取不到节点时返回 `self`，所以 headless / 直接 `new ArpgMain()` 的场景照常工作，
不依赖 `.tscn`。这是「可复用」的关键——容器是组织手段，不是运行前提。

### 2.4 中文化

**第一版为什么不生效**：`TranslationServer.add_translation()` 只写**主域**（运行时 `tr()` 用的那个），
而编辑器查属性名走的是**独立的域**。Godot 的 `TranslationServer` 在编辑器下挂了三个域：

| 域 | 用途 |
|---|---|
| 主域（main_domain） | 运行时 `tr()` |
| `godot.editor` | 编辑器 UI（菜单/按钮/对话框） |
| `godot.properties` | **检查器属性名**（Position / Rotation / Scale 就是从这取的） |

所以必须显式 `get_or_add_domain("godot.properties").add_translation(...)`，只调
`add_translation()` 永远不会影响检查器——这是上一版「明明加了词表却全是英文」的真正原因。

现在 `addons/arpg_zh_editor/plugin.gd` 同时注入主域 + `godot.editor` + `godot.properties`，
词表覆盖三块：Node / CanvasItem / Node2D 的内置属性名与分组名、本项目的三组导出变量标签
（`Start Floor`→起始层 等；变量名是 ASCII，标签只能靠翻译补）。

三条安全约束：

1. **只在中文环境注入**（`locale.begins_with("zh")`），英文环境不受影响；
2. 词表只覆盖检查器短词，不碰有业务含义的长句；
3. `_exit_tree` 从所有域摘掉，禁用插件即完全还原；
4. `get_or_add_domain` 有 `has_method` 保护——该 API 是 4.4+ 才有的，旧引擎只走主域，
   绝不让插件在 `_enter_tree` 抛错（那会被编辑器判定为加载失败）。

**为什么导出变量名不能用中文（踩过的坑）**：`.tscn / .tres` 的裸标识符走
`VariantParser`，其字符判定是 `is_ascii_alphabet_char` + `is_underscore`——**ASCII-only**。
一旦中文变量名随场景保存（`说明 = "..."` 这种），场景文件就再也读不回来。
所以所有 `@export` 变量必须是 ASCII，中文标签只能通过翻译域补；
节点名（`"世界"`）走的是带引号字符串，不受这个限制。

**容器节点干脆不定义任何 `@export`**：它们只需要「别显示一堆没用的英文」，
所以用 `_validate_property` 把内置属性全部隐藏，检查器留空即可。
需要临时调节点位置时改脚本里的 `const SHOW_RAW := true`（用常量而不是导出变量，
就是为了不产生会被写进 `.tscn` 的字段）。

启用方式：`project.godot` 的 `[editor_plugins]` 已写入，打开编辑器自动加载；
也可在「项目 → 项目设置 → 插件」里手动开关。插件加载时会在「输出」面板打印
`[中文化] 已注入 N 条术语到 3 个域`，可用它确认是否生效。

**能力边界（必须说清）**：这只能补「词表里列出的」术语。Godot 引擎自身还有大量
专业术语（着色器、导入器、调试器内部项）保持英文——那些在引擎二进制里，
不重新编译引擎无法替换。本方案的目标是「日常写玩法时不再被英文属性挡住」，
不是「把整个引擎汉化成不认识的技术名词」。

## 三、怎么用

### 打开就能看到地图

1. 双击 `arpg/main.tscn`；
2. 选中「编辑器预览」节点，按 **F** 把视图框到整张地图；
3. 右侧检查器改「层号 / 种子 / 换一张图」，画面立即重绘。

### 调玩法参数

选中根节点 `ArpgMain`，检查器顶部就是「开局 / 地牢」两组中文参数，改完直接 F5 生效。
（想改数值平衡仍然走 `data/balance.json`，保存即热重载，不用重启。）

### 改颜色

预览层配色在 `editor_preview.gd` 顶部常量（`COL_FLOOR` / `COL_BG` / `COL_ROOM_*`），
与游戏内小地图共用同一套灰白色系。

## 四、后续可扩展的方向

| 方向 | 做法 | 收益 |
|---|---|---|
| 房间级编辑 | 预览层支持框选房间 → 写回排布约束 | 手工微调布局 |
| 刷怪预览 | 按层号读取敌人池，在房间里画密度热力 | 一眼看出战斗节奏 |
| 数值面板 | `@tool` 节点把 `balance.json` 关键段画成表格 | 不用开 JSON |
| 词表扩充 | 往 `TERMS` 加词，随用随加 | 中文覆盖率递增 |

---

## 五、约束

- 预览层**不写任何游戏状态**，只读 `balance.json` 与生成器；删掉它游戏照跑。
- 容器节点是组织手段：`_slot()` 取不到就退回 `self`，不构成运行依赖。
- 中文化插件只影响显示，不影响 `get_class()` / `is` 判断 / 存档字段。
