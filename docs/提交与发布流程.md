# 提交与发布流程

本仓库的提交走**两条路径**，默认用 A，A 被网络掐断时用 B。

---

## 一、凭据从哪来

GitHub Desktop 登录过一次之后，token 就存在 **Windows 凭据管理器**里。
git 和下面的脚本都用同一份，**不需要手填 PAT，也不需要装 `gh` CLI**。

```bash
git credential fill <<'EOF'
protocol=https
host=github.com

EOF
```

能打印出 `username=x-access-token` 和 `password=...` 就说明凭据可用。
`tools/gh_pr.py` 内部就是调这条命令取 token，**不写文件、不回显**。

---

## 二、路径 A：git push（默认，最快）

实测可用（2026-11-03 两次推送成功，419 文件的提交约 1 分钟）。

```bash
git checkout -b feature/xxx
git add -A && git commit -F - <<'MSG'
feat: ...
MSG
git push -u origin feature/xxx
python tools/gh_pr.py pr --title "feat: ..." --merge
```

`gh_pr.py pr` 做的事：推分支 → 建 PR → 合并，一次跑完。
加 `--body-file docs/pr.md` 可以把 PR 描述写成文件；`--method squash` 换合并方式。

> 推送时遇到 `CONNECT tunnel failed, response 502` 是网络策略问题，
> 不是凭据问题。等一会儿重试，或直接走路径 B。

---

## 三、路径 B：GitHub Contents API（兜底）

git 完全不通时，用 API 直接改文件。只能单个文件，适合改文档、热修一行。

```bash
python tools/gh_pr.py put --path docs/某文档.md --message "docs: 更新说明"
```

它做的事情：`GET /contents/{path}` 拿当前 sha → `PUT /contents/{path}` 提交 base64 内容。
新建和更新都支持（有 sha 就是更新）。

**注意**：这是「直接提交到分支」，不经过工作区，所以本地文件会落后。
用它之后记得 `git pull` 一次，否则下次 `git push` 会冲突。

### 为什么不用 Git Data API 批量传

批量上传需要「逐文件建 blob → 建 tree → 建 commit → 更新 ref」四步，419 个文件就是 419 次请求，
既慢又容易中途失败。既然 `git push` 这条通道本身是通的，就没必要自己重造一遍 git。

## 五、常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| `502 / CONNECT tunnel failed` | 网络策略拦截 | 重试或走路径 B |
| `取不到 GitHub 凭据` | GitHub Desktop 未登录 | 用 GitHub Desktop 登录一次 |
| PR 报 `a pull request already exists` | 分支已有开放 PR | 脚本会自动复用那个 PR |
| 合并后本地落后 | 合并是在远端做的 | `git checkout main && git pull` |
| 文件超过 100MB | GitHub 硬限制 | 别提交，改用 Release 附件 |
